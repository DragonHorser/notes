## 一、网络协议

### 1. IP

- **IP地址**：计算机设备在网络里的唯一标识（身份证）
- **IP作用**：根据 IP 从网络里找到某一台计算机设备
- **IP分类**：
  - **IPv4**：示例 `192.168.40.117`
  - **IPv6**：冒号分隔的十六进制值，如 `1234:abcd:a1b2:...`
- **需要掌握**：
  - 查看本机 IP：`ipconfig`
  - 始终指向本机的 IP：`127.0.0.1` 或 `localhost`

### 2. 端口

- **作用**：计算机里的软件与外界进行数据交互时的虚拟出入口
- **范围**：`0 ~ 65535`
- **特点**：抢占式资源
  - 一个端口被某个程序占用后，其它程序不能再占用
  - 例如：`3306` 端口被 MySQL 使用

### 3. HTTP

- **全称**：超文本传输协议
- **作用**：规定客户端和服务端之间数据交互的格式
- **特点**：
  - **基于文本**：所有交互数据都是字符串，底层 TCP 稳定可靠
  - **请求驱动**：先有请求，才有响应
    - 请求：客户端发给服务端的数据
    - 响应：服务端返回客户端的数据
  - **无状态**：两次请求之间，后端没有记忆

#### HTTP 请求

前端发送给后端的数据，由三部分组成：

##### 请求行

- 本次请求的基本信息
- 格式：`请求方式 请求资源 协议版本`
- 示例：`GET /courses/1 HTTP/1.1`
- **请求方式**：
  - 查询：`GET`
  - 新增：`POST`
  - 修改：`PUT`
  - 删除：`DELETE`

##### 请求头

- 本次请求的附加信息（很多由浏览器自动附加）
- 格式：一行一个键值对，用英文冒号分隔

##### 请求体

- 本次请求提交的正文数据
- `POST` 或 `PUT` 时提交的数据（要保存或修改的数据）
- `GET` 和 `DELETE` 没有请求体，提交的数据写到请求行里请求资源的后边

#### HTTP 响应

后端返回给前端的数据，由三部分组成：

##### 响应行

- 本次响应的基本信息
- 格式：`协议版本 响应状态码`
- **响应状态码**：3 位整数，告诉前端本次处理结果
  - **1xx**：过程码，通常见不到
  - **2xx**：成功码
  - **3xx**：告诉前端需要下一步操作
    - `304`：后端告诉前端去找缓存数据
  - **4xx**：前端出错
    - `400`：Bad Request
    - `403`：没有权限访问
    - `404`：请求的资源不存在，检查路径
  - **5xx**：后端出错
    - `500`：服务器内部错误
    - `503`：后端服务不可用

##### 响应头

- 本次响应的附加信息
- 格式：一行一个键值对，用冒号分隔

##### 响应体

- 本次响应的正文内容，是后端返回给前端的结果数据
