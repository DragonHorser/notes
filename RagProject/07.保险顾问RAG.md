## LangChain-Milvus

### 使用步骤

#### 1. 连接上 Milvus

```python
client = Milvus(
     connection_args={ 'uri': Milvus的连接地址 },
     collection_name="集合名称",
     vector_fields=[ 'dense', 'sparse' ],
     embedding_function=向量模型,
     builtin_function=BM25BuiltInFunction( analyzer_params={'type':'chinese'} ),
     auto_id=是否由Milvus自动生成主键
)
```

> 这一步不会创建集合，仅仅是配置好了各种参数。

#### 2. 添加文档

如果集合不存在，会自动创建集合，再添加文档。

```python
client.add_documents( 文档列表 )
```

- **主键值**：我们设置了自动生成
- **稀疏向量和稠密向量**：我们已经提供了向量模型和稀疏向量的函数，不需要再关心
- **其它字段**：`Document` 里的 `metadata` 中，每个元数据会自动对应集合里的一个列

#### 3. 删除文档

```python
client.delete( ids = id列表)
client.delete( expr = 'h2=="第一节 中外教育家及其教育思想" ' )
```

#### 4. 检索文档

只要集合里有稀疏向量，LangChain-Milvus 将会自动开启混合检索，必须要指定混合检索相关的策略：

- 加权融合
- RRF 融合
- **【推荐】重排序**

```python
def create_cross_encoder_ranker(queries: list[str]):
    return Function(
        name="dashscope_semantic_ranker",  # ranker名词，唯一即可
        input_field_names=["text"],  # 原始文档字段
        function_type=FunctionType.RERANK,  # ranker类型，这里是固定值
        params={
            "reranker": "model",  # rerank类型，基于模型rerank，也就是cross-encoder
            "model_name": "gte-rerank-v2",  # rerank模型名称
            "provider": "ali",  # rerank模型提供者
            "queries": queries,  # 查询条件
            "max_client_batch_size": 5,  # 向模型发送请求时的批处理限制
        },
    )
```

```python
client.similarity_search(
     query = "用户的问题",
     k=最终检索结果的数量,
     fetch_k=每一路检索要抓取多少条文档,
     reranker=create_cross_encoder_ranker( [用户问题] )
)
```

## 保险顾问 RAG

### 方案

#### 文档加载

MinerU

#### 文档切分

- 先结构感知切分：根据章节标题拆分出一个个的章节
- 再使用递归切分：如果章节内容过长，再递归切分

#### 存储与检索

**存储方案：**

大块存储到数据库

每个大块包含：

- 大块 ID
- 所属保险产品 ID
- 条款文件名称
- 大块内容
- 所属章节路径

数据表结构

小块存储到向量库

每个小块包含：

- 所属大块 ID
- 所属保险产品 ID
- 主键：不需要我们关心，由 Milvus 自动生成
- `text`：小块内容
- 2 个向量字段

小块示例

**检索方案：**

- 利用小块做精准检索：用户提问了，从向量库里做精准检索，得到相关的小块
- 利用大块提供完整条款：再到数据库里找小块所属的大块，将大块内容拼接提示词给大模型做回答
