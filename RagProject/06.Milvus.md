## Schema

相当于 MySQL 里的表结构，即一个集合里有哪些 Field，每个 Field 是什么类型，有什么限制约束等等。

**每个 Field 我们要考虑：**

- **列名称**
- **列类型**
  - 整数：`INT32`、`INT64`
  - 字符串：`VARCHAR`
  - 稠密向量：`FLOAT_VECTOR`
  - 稀疏向量：`SPARSE_FLOAT_VECTOR`
- **列描述**

### 两种向量的理解

#### 稠密向量

- **用于**：根据语义相似度检索
- **结构**：维度固定，比如 1024 维，每一维度都有值
- **结构示例**：`[ 0.11, 0.22, .... ]`
- **计算**：使用模型 `text-embedding-v4` 向量模型

#### 稀疏向量

- **用于**：根据关键词精准匹配检索
- **结构**：维度非常高，几万 ~ 几十万维，但是绝大部分维度值都是 0
- **结构示例**：`{ 索引:权重, 索引:权重, ... }`
  - 每个索引对应了词表中的一个关键词
- **计算**：统计式的 BM25 或者学习式 BGE-M3 模型

## Index

索引，作用是用于提升查询数据速度的一种数据结构。

| 字段类型             | 索引类型                |
| -------------------- | ----------------------- |
| 普通字段（标量字段） | `AUTOINDEX` 自动索引    |
| 稠密向量字段         | `AUTOINDEX` 自动索引    |
| 稀疏向量字段         | `SPARSE_INVERTED_INDEX` |

## Milvus 的集合操作

### 创建集合

每个集合都需要指定：

- **集合名称**
- **schema**：有哪些字段
  - 字段名 + 数据类型 + 其它限制
  - `id` 主键字段：`id`，类型 `INT64`，`is_primary=True`
  - 普通字符：`h2`，类型 `VARCHAR`，`max_length=128`
  - 普通字符：`text`，类型 `VARCHAR`，允许分词，采用中文分词，目的是为了让 Milvus 替它生成稀疏向量
  - 稀疏向量：`sparse`，类型 `SPARSE_FLOAT_VECTOR`
  - 稠密向量：`dense`，类型 `FLOAT_VECTOR`，维度 1024
  - 再添加一个函数：根据 `text` 字段计算稀疏向量数据，可使用 BM25 统计式算法
- **index**：给哪些字段加索引
  - 普通字段的索引：`AUTOINDEX`
  - 稠密向量的索引：`AUTOINDEX`
  - 稀疏向量的索引：`SPARSE_INVERTED_INDEX`

```python
client.create_collection(collection_name=集合名, schema=集合schema, index_params=集合的索引)
```

### 查看集合

```python
client.list_collections()
```

### 删除集合

```python
client.drop_collection(collection_name=集合名)
```

## Milvus 的 Entity 操作

### 添加数据到集合

```python
client.insert(collection_name=集合名, data=数据列表)
```

**数据列表：**

- 每一条数据是一个字典

```python
{
   "字段名": 值,
   "字段名": 值,
   ....
}
```

  - 稠密向量需要我们手动利用向量模型生成
  - 稀疏向量由 Milvus 的函数自动计算
- 多条数据组装成一个列表

### 修改数据

```python
client.upsert(collection_name=集合名, data=数据列表)
```

如果一条数据：

- `id` 不存在：会新增
- `id` 已存在：会覆盖

### 删除数据

```python
client.delete(collection_name=集合名, ids=id列表)
```

### 检索数据

#### 单纯用稠密向量检索

```python
client.search(
     collection_name="集合名",
     anns_field="稠密向量字段名",
     data=[用户问题的向量],
     search_params={"metric_type": "COSINE"},
     limit=5
)
```

- **适合**：语义检索
- **不适合**：关键词检索

#### 单纯用稀疏向量检索

```python
client.search(
     collection_name="集合名",
     anns_field="稀疏向量字段名",
     data=[用户问题字符串],
     search_params={"metric_type": "BM25"},
     limit=5
)
```

- **适合**：关键词检索
- **不适合**：语义检索

#### 混合检索

**2 路检索，加权融合**

- 根据 2 路检索结果中，每个文档的相似度得分和权重计算最终得分
- `稠密向量得分 * 稠密权重 + 稀疏向量得分 * 稀疏权重 => 此文档的最终得分`

**2 路检索，RRF 融合**

- 根据 2 路检索结果中，每个文档的排名计算最终得分
- `1 / (60 + 稠密向量排名) + 1 / (60 + 稀疏向量排名) => 此文档的最终排名`

**2 路检索，重排序**

使用 Cross-Encoder 交叉编码的方式进行重排。

| 编码方式               | 特点                               | 适合                                                         |
| ---------------------- | ---------------------------------- | ------------------------------------------------------------ |
| Bi-Encoder 并行编码    | 检索结果的精度较差，检索的速度很快 | 初筛：利用稠密向量检索/稀疏向量检索，从海量文档里找到相关的部分文档 |
| Cross-Encoder 交叉编码 | 检索结果的精度更高，检索的速度较慢 | 精排：基于初筛的结果做再排序                                 |

Cross-Encoder 精排流程：

- 将初筛结果的文档列表和用户问题，一起交给 rerank 模型
- 由 rerank 模型基于用户问题，对这些文档作重新打分排名

**最终的检索流程：**

1. **初筛**
   - 利用稀疏向量做关键词匹配检索
   - 利用稠密向量做语义匹配检索
2. **精排**
   - 针对初筛结果（少量文档）+ 用户问题，交给 rerank 模型，作重新打分排名
   - 数据量少，且结果比较精准
