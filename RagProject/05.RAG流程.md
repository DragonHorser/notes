## RAG 流程

### RAG 概念

检索增强生成

- **检索**：从向量库里检索相似的文档片段
- **增强**：提示词包含用户问题和相关片段，对模型进行增强
- **生成**：生成最终的回答

### 整体流程

**阶段1：离线阶段 - 构建知识库**

1. 加载文档
2. 切分文档
3. 向量化
4. 存储到向量库

**阶段2：在线阶段 - 检索增强生成**

1. 用户问题向量化
2. 从知识库（向量库）中检索相关的片段
3. 拼接提示词，调用大模型得到回答

### 细节说明

#### 为什么要切分文档

- 如果不切分的话，提示词包含了用户问题 + 整个文档
  - 消耗的 token 巨大，成本高
  - 模型的上下文窗口有限，提示词过长会被截断

#### 为什么要向量化

**什么是向量：**

- 一组有序的数字集合，在空间里表示为有方向的箭头

**为什么要向量化：**

- 计算机不识字，要实现相似性计算，就需要向量化
- 将文本内容/图片/音频/视频等等，转换为向量数据
- 然后模型计算不同向量之间的距离，来判断它们的相似性

**两个向量的距离：**

- 距离意味着 2 段文本的相似度
- 距离计算的方式
  - **余弦相似度 COSINE**：2 个向量的夹角，角度越小，说明语义越相似
  - **欧氏距离**：2 个向量在空间中的直接距离，受长度影响
  - **点积**：一个向量在另一个向量上的投影，受长度影响

**向量数据存储与检索：**

- 使用向量数据库
- 常用的向量数据库：
  - **Milvus**：工业级的向量数据库
  - **Chroma**：轻量的向量数据库
  - **PostgreSQL**：也支持向量存储与检索
  - **ElasticSearch**
  - **Redis**

## 阶段1 - 离线 - 构建知识库

### 加载文件

LangChain 内置了加载器。

- 通用的加载方法：`load()`，返回 `list[Document]`
- 每个 `Document` 里有：
  - `metadata`：文档的元数据
  - `page_content`：文档的内容字符串

**加载 PDF 的强大工具：**

- IBM 的 **Docling**
- 国产 **MinerU**
  - 快速解析（轻量）：

```python
client = MinerU()
result = client.flash_extract(source="文件路径", is_ocr=True)
```

> `result.markdown` 得到解析的结果，是 md 格式的字符串。

  - 精准解析：

```python
client = MinerU(token=身份令牌)
result = client.extract(source="文件路径", ocr=True)
```

> `result.markdown` 得到解析的结果，是 md 格式的字符串。

### 文本切分

#### 常用策略

| 策略 | 说明 |
| --- | --- |
| 递归切分 | 按照不同的分隔符，先切大块，再切小块 |
| 结构感知切分 | 根据文档的结构进行切分 |

#### 递归切分

**切分步骤：**

```python
splitter = RecursiveCharacterTextSplitter(
    separators=[分割符, 分割符, ...],
    chunk_size=每一块的最大长度,
    chunk_overlap=块之间重叠的字符数量
)
```

**执行过程：**

- 先按照第 1 个分隔符切分文档
- 处理切分结果：
  - 块小，就合并起来，不超出 `chunk_size`
  - 块大，根据第 2 个分隔符切分文档

### 向量库

**常用的向量库：**

- Milvus
- Chroma
- InMemoryVectorStore：练习使用的向量库，向量数据存储在内存中

**向量库的使用：**

1. 初始化向量库

```python
vector_store = InMemoryVectorStore(embedding=向量模型)
```

2. 添加文档到向量库中

```python
vector_store.add_document(文档列表)
```

3. 从向量库中删除文档

```python
vector_store.delete( ids=[文档id, 文档id, ...] )
```

4. 根据问题检索相似的文档片段

```python
vector_store.similarity_search( query="用户问题", k=检索数量 )
```

> 得到的结果是 `list[Document]`。

## 阶段2 - 在线 - 检索增强生成

### 方式1：2-step RAG

1. 用户提问
2. 检索知识库，得到相关片段
3. 拼接提示词：用户问题 + 相关片段
4. 调用智能体得到回答

### 方式2：Agentic RAG

将检索知识库封装成工具，挂载给 Agent 智能体，由智能体判断是否需要检索知识库。
