## 项目介绍

> 大家脑海里要有一个意识：每个项目必须要立得住，即每个项目一定是有非常大的价值，一定是能为公司解决很大的麻烦。

### 项目背景

为什么要有这个项目，是为了解决什么问题而出现的。

**可以先介绍安心保项目：**

- 是一个在线的保险销售平台，对接各大保司的不同保险产品，用户可以在安心保平台自由浏览保险产品、组合保险产品、购买保险

**再说明没有 AI 顾问时的问题：**

当用户购买保险时，通常不知道要购买哪些产品合适、不了解保险产品的细则、不清楚保险产品的理赔规则等等。

原本由客服出面为用户解决这些问题，但是存在比较大的麻烦：

- **客服响应速度慢**
  - 首先客服也需要查阅保险产品的各种文档手册
  - 然后客服人数有限，一旦用户数量多，就会出现排队情况
  - 客服不能 24 小时提供服务
- **客服培训成本高**
  - 对客服的专业素养要求高，一旦客服表现不专业，会导致客户流失
  - 为了让客服能够为用户提供专业的服务，需要提前进行业务培训

**最后说 AI 顾问的价值所在：**

如果用户有购买保险产品的疑问，可以直接咨询 AI 顾问。

AI 顾问的好处：

- 7*24 小时在线服务
- 响应速度快
- 有效降低保险代理商的客服相关成本

### 项目结构

结合原安心保项目，提供了 AI 顾问功能。

和 AI 顾问相关的主要有 2 个端（系统的 2 个访问入口）：

- **后台管理端**：给保险代理商用于管理各种数据、产品、订单等等
- **用户端**：普通用户用来浏览产品、购买保险、咨询顾问

### 技术架构

**前端相关技术：** React + Ant Design

**后端相关技术：**

- Python + FastAPI + SQLAlchemy
- LangChain + LangGraph + MinerU + Deepseek + BEG-M3

**数据存储层面：**

- PostgreSQL + Milvus

**项目部署相关：**

- docker compose

## 环境搭建

把项目代码运行起来（跑起来），熟悉项目结构和规范。

### 项目里的配置参数怎么处理的？

参数都放在 `.env` 文件里。

> **提示**：好处是如果要修改参数的话，不需要调整源码。

使用 `pydantic-settings` 读取 `.env` 里的参数。

如果代码里需要使用参数，项目里：

- `settings.db`：获取数据库相关参数
- `settings.app`：获取项目相关的参数
- `settings.llm`：获取大模型相关的参数
- `settings.loggings`：获取日志相关的参数

### 项目里的日志是怎么处理的？

项目里已经提供了日志相关的模块代码（彩色日志）。

如果我们要打印日志，怎么做？

```python
logger = get_logger(__name__)
logger.info()
logger.warning()
logger.error()
```

### 项目的目录结构

按照业务功能划分包的。

**保险产品相关的功能，全部放在 `app.modules.product` 包里：**

| 文件 | 说明 |
| --- | --- |
| `schemas.py` | 放对应请求参数的类和响应结果的类 |
| `models.py` | 放对应数据库表的实体类 |
| `router.py` | 放路由函数。职责：只负责接收请求参数，返回响应结果 |
| `service.py` | 放业务的类。职责：负责实现业务功能，处理数据、转换数据、处理事务等等 |
| `repository.py` | 放数据操作类。职责：负责读写数据库，执行 SQL 语句 |

**AI 会话相关的功能，全部放在 `app.modules.conversions` 包里。**

**用户管理相关的功能，全部放在 `app.modules.user` 包里。**

## 分层思想

**核心目的：** 为了实现代码解耦，达到"低耦合"。

- **什么是耦合**：代码之间的关联性
- **如果是强耦合**：不同功能代码之间，一个功能代码变化，其它功能代码受影响
- **追求低耦合**：不同功能代码之间，如果某个功能代码变化，对其它功能代码影响很小，甚至不影响
- **如何做到低耦合**：拆分。一个功能（函数/方法）只做一件事

### 分层思想

#### router 层

- 负责接收请求参数，返回响应结果
- 不负责执行 SQL 语句、不负责处理数据组装数据处理事务等等

#### service 层

- 负责处理业务功能，比如处理数据、组装数据、处理事务等等
- 不负责执行 SQL 语句

#### repository 层

- 负责执行 SQL 语句
