## 第一部分：RAG 离线建库核心流程

离线阶段的核心目标：把本地各种格式的文档，变成向量库里能够被检索的数字（向量）。

### 1. 文档加载与切分

**设计逻辑**：为了兼顾"检索精度"和"语义完整度"，通常采用结构感知切分（按 Markdown 标题切分），并保留元数据。

```python
from langchain_text_splitters import MarkdownHeaderTextSplitter

# 按层级切分，保留标题在 metadata 中
markdown_splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=[("#", "h1"), ("##", "h2"), ("###", "h3")],
    strip_headers=False # 正文中保留标题，方便模型理解上下文
)
docs = markdown_splitter.split_text(markdown_text)

# 给每个切片打个 id，方便后续更新、删除或追溯来源
for i, doc in enumerate(docs, start=1):
    doc.id = f'doc_{i}'
```

### 2. 向量化与存储

**代码逻辑**：使用本地 Ollama 或云端模型，将文本切片转为多维数组，存入内存库或 Milvus。

```python
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_ollama import OllamaEmbeddings

# 【核心踩坑记录】
# 1. Ollama 模型名必须与 `ollama list` 中一模一样。
# 2. 必须用官方支持 embedding 的模型（如 qwen3-embedding:0.6b 或 bge-m3）。
#    如果用第三方打包版，会报 501 (This server does not support embeddings)。
embeddings = OllamaEmbeddings(model="qwen3-embedding:0.6b", dimensions=1024)

# 【踩坑记录】Jupyter 中读取文件报 FileNotFoundError，是因为路径 '/' 开头代表根目录。
# 正确写法：相对路径 './resources/评估.md' 或使用 os.path.abspath 获取绝对路径。

# 初始化内存库（重启 Jupyter 后数据会丢失，仅用于测试）
vector_store = InMemoryVectorStore(embedding=embeddings)
vector_store.add_documents(docs)
```

## 第二部分：在线检索与 Agentic RAG

在线阶段的核心目标：把用户问题变成向量，去库里精准捞取相关的知识片段。

### 1. 基础检索与常犯错误

```python
query = "论语中教育的目的"

# 【踩坑记录】similarity_search 返回 list[Document]。
# 如果写成 `for doc, score in results:` 会报 ValueError (too many values to unpack)。
# 想看分数，必须用 similarity_search_with_score
results = vector_store.similarity_search_with_score(query, k=5)

for doc, score in results:
    print(f"得分: {score}, 内容: {doc.page_content}")
```

### 2. 进阶架构：Agentic RAG

**设计逻辑**：传统的 2-Step RAG 每次都会盲目检索（连问"你好"都会去查库）。Agentic RAG 把检索封装成 Tool，让大模型自主判断是否需要查资料。

```python
from langchain.tools import tool
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain_core.messages import HumanMessage

# 1. 封装检索工具
@tool
def retrieve_docs(query: str):
    """检索教资知识库，获取知识片段"""
    docs = vector_store.similarity_search(query, k=2)
    # 工具必须返回字符串给大模型
    return "\n\n".join(doc.page_content for doc in docs)

# 2. 初始化大模型
model = init_chat_model("deepseek-v4-flash", extra_body={"thinking": {"type": "disabled"}})

# 3. 创建 Agent
agent = create_agent(
    model=model,
    tools=[retrieve_docs],
    system_prompt="你是一个专家，你调用工具检索文档回答用户问题。文档中没有的不要编造。"
)

# 4. 调用（大模型会自动提取关键词去检索，即 Query Rewriting）
response = agent.invoke({'messages': [HumanMessage(content="论语中教育的目的")]})
```

## 第三部分：Milvus 核心概念与混合检索

从 `InMemoryVectorStore` 升级到 Milvus，是为了数据的持久化和海量数据的高效检索。

### 1. 核心概念映射

| Milvus 概念 | 对应关系 |
| --- | --- |
| Collection | 表（Table） |
| Field | 列（Column，包含主键、向量、标量字段） |
| Entity | 行（Row，具体的每一条数据） |
| Schema | 表结构定义 |

### 2. 稠密 vs 稀疏

| 类型 | 原理 | 擅长 |
| --- | --- | --- |
| 稠密向量 | 基于深度学习生成 | 懂语义（问"怎么赔"，能搜到"理赔流程"） |
| 稀疏向量 | 基于词频统计（如 BM25） | 懂专有名词（搜"甲状腺癌"，绝不匹配"甲状腺炎"） |

### 3. Milvus 建表与多路召回代码

```python
from pymilvus import MilvusClient, DataType, AnnSearchRequest, RRFRanker

client = MilvusClient(uri="http://127.0.0.1:19530")
collection_name = "insurance_collection"

# 1. 定义 Schema
schema = client.create_schema(auto_id=False)
schema.add_field(field_name="id", datatype=DataType.INT64, is_primary=True)
schema.add_field(field_name="dense", datatype=DataType.FLOAT_VECTOR, dim=1024) # 稠密
schema.add_field(field_name="sparse", datatype=DataType.SPARSE_FLOAT_VECTOR)    # 稀疏(BM25)
schema.add_field(field_name="content", datatype=DataType.VARCHAR, max_length=2048)
schema.add_field(field_name="product_id", datatype=DataType.INT64) # 标量过滤字段

# 2. 建索引（稠密用 AUTOINDEX，稀疏用倒排）
index_params = client.prepare_index_params()
index_params.add_index(field_name="dense", index_type="AUTOINDEX", metric_type="COSINE")
index_params.add_index(field_name="sparse", index_type="SPARSE_INVERTED_INDEX", metric_type="BM25")
client.create_collection(collection_name, schema=schema, index_params=index_params)

# ==========================
# 3. 混合检索 (Hybrid Search)
# ==========================
# 构造双路请求
dense_req = AnnSearchRequest(data=[query_dense_vector], anns_field="dense", param={"metric_type": "COSINE"}, limit=3)
sparse_req = AnnSearchRequest(data=[query_text], anns_field="sparse", param={"metric_type": "BM25"}, limit=3)

# 融合策略：RRF（只看排名，不看绝对分数，最常用）
ranker = RRFRanker(k=60)

# 执行带过滤条件的混合检索（只在特定 product_id 内搜）
res = client.hybrid_search(
    collection_name=collection_name,
    reqs=[dense_req, sparse_req],
    ranker=ranker,
    limit=5,
    filter="product_id == 100", # 标量过滤，极速缩小检索范围
    output_fields=["content", "product_id"]
)
```

## 第四部分：终极架构 - 父子块切分

解决"切块太大搜不准，切块太小没上下文"的终极企业级方案。

### 1. 架构设计图

- **父块（Parent）**：大片段，存 PostgreSQL。用于给大模型提供完整的上下文。
- **子块（Child）**：小片段，存 Milvus。用于高精度的向量召回。

### 2. 离线切分代码逻辑

```python
sections = markdown_splitter.split_text(markdown)
parent_chunks = []
child_chunks = []

for section in sections:
    # 1. 生成父块
    parent = ParentChunk(id=uuid4(), content=section.page_content, ...)
    parent_chunks.append(parent)
    
    # 2. 子块继承父块的 ID
    section.metadata = {"parent_id": str(parent.id)}
    
    # 3. 切成子块
    children = child_splitter.split_documents([section])
    child_chunks.extend(children)

# 4. 分别入库
save_to_postgres(parent_chunks)
save_to_milvus(child_chunks)
```

### 3. 在线检索代码逻辑

```python
# 1. 去 Milvus 查子块（混合检索+Rerank）
child_docs = milvus_client.search(query_vector)

# 2. 提取 parent_id 并去重
parent_ids = list(set([doc.metadata["parent_id"] for doc in child_docs]))

# 3. 去 PostgreSQL 查父块（拿到完整条款）
parent_chunks = await pg_repo.list_by_ids(parent_ids)
```

## 高频面试题预演

**问：你的 RAG 系统检索准确率怎么保证？**

答：使用了混合检索（Dense 语义 + BM25 关键词），并带有 Metadata 过滤（比如指定 `product_id`），最后还加入了 Rerank 模型进行二次精排。

**问：切块策略怎么选？**

答：先用 Markdown 结构感知切分，针对超长块用递归切分，并采用了父子块架构，子块负责在 Milvus 中被精准搜到，父块负责在 PG 中被提取出来喂给大模型，完美平衡了精度与上下文完整性。

**问：文档更新了怎么办？**

答：依据业务主键（如 `product_id`）先删除 Milvus 和 PostgreSQL 中的旧数据，再重新执行 RAG Pipeline 跑一遍入库，保证数据一致。

**问：RAG 和微调（Fine-tuning）的区别？**

答：RAG 是外挂知识库，解决"不知道"的问题，适合动态更新的数据；微调是改变模型权重，解决"不会做特定任务/格式"的问题，适合固定场景。
