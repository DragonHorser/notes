# SQL 窗口函数完全指南 (Window Functions Cheatsheet)

> 窗口函数（Window Functions）是 SQL 进阶的必修课。它的核心思想是：**在不改变原表行数的情况下，对数据进行跨行计算，并将结果作为新列附加在原数据旁边。**

## 一、 核心语法结构（万能公式）

窗口函数的完整语法如下，中括号 `[]` 内为可选项：

```sql
函数名([参数]) OVER (
    [PARTITION BY 分组字段1, 分组字段2...]  -- 1. 分区：将数据分成不同的小组
    [ORDER BY 排序字段 [ASC|DESC]]          -- 2. 排序：在组内排序（决定行号、累计等）
    [ROWS|RANGE BETWEEN 边界1 AND 边界2]    -- 3. 滑动窗口：指定计算范围（帧）
)
```

> 💡 **核心心法**：`GROUP BY` 会把多行压缩成一行，而 `OVER()` **不改变原表行数**，只是把计算结果当成新列“贴”在每一行旁边。

## 二、 四大类窗口函数全收录

### 1. 聚合类（最常用，把常规聚合函数窗口化）
在聚合函数后加 `OVER()`，就能保留明细行。

| 函数 | 作用 | 场景举例 |
| :--- | :--- | :--- |
| `SUM()` | 求和 | 算占比（当前值/总体总和） |
| `COUNT()` | 计数 | 算分组内总行数、算累计行数 |
| `AVG()` | 平均值 | 对比当前值与部门平均值 |
| `MAX()` / `MIN()` | 最大/最小值 | 算当前值与该组最高值的差距 |

### 2. 排名类（Top-N 问题必用）
这三个函数必须配合 `ORDER BY` 使用。

| 函数 | 特点 | 示例（成绩：99, 99, 95） |
| :--- | :--- | :--- |
| `ROW_NUMBER()` | **绝对排名**，永不重复，遇到相同值按出现顺序排。 | 1, 2, 3 |
| `RANK()` | **跳跃排名**，并列后留空位。 | 1, 1, 3 |
| `DENSE_RANK()` | **密集排名**，并列后不留空位。 | 1, 1, 2 |
| `NTILE(N)` | **分桶**，将数据按顺序尽量平均分成 N 份。 | 若N=2，结果为 1, 1, 2 |

### 3. 偏移类（算同比、环比、留存率必用）
获取当前行的前/后 N 行数据。

| 函数 | 作用 | 语法及参数 |
| :--- | :--- | :--- |
| `LAG()` | 获取**前** N 行的值 | `LAG(字段, N, 默认值)`，N可省略默认1 |
| `LEAD()` | 获取**后** N 行的值 | `LEAD(字段, N, 默认值)` |

### 4. 头尾取值类（取分组内最新/最旧记录）
不需要复杂的自连接。

| 函数 | 作用 | 语法及参数 |
| :--- | :--- | :--- |
| `FIRST_VALUE()` | 获取窗口内**第一行**的值 | `FIRST_VALUE(字段)` |
| `LAST_VALUE()` | 获取窗口内**最后一行**的值 | `LAST_VALUE(字段)`（**⚠️注意下方避坑指南**） |
| `NTH_VALUE()` | 获取窗口内**第 N 行**的值 | `NTH_VALUE(字段, N)` |

### 5. 分布类（算百分位、中位数）
数据分析师最爱。

| 函数 | 作用 |
| :--- | :--- |
| `PERCENT_RANK()` | 计算相对排名百分比（0 到 1 之间） |
| `CUME_DIST()` | 计算累积分布（小于等于当前值的比例） |

## 三、 滑动窗口 Frame（进阶重点）

在 `OVER()` 里写 `ROWS BETWEEN ... AND ...`，用于规定**“当前行计算时，到底要看前后多少行”**。不写的话默认看全部。
这在算**移动平均（如近7天销量）、累计求和**时必用。

**常用边界写法：**
*   `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`：从第一行加到当前行（**累计求和**）。
*   `ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING`：当前行的上一行、当前行、下一行的数据（**3日移动平均**）。
*   `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW`：当前行及前 6 行（**近7日移动平均**）。
*   `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`：当前分区的所有行。

> *注：`ROWS` 按物理行数算，`RANGE` 按数值范围算（比如按日期范围）。一般用 `ROWS` 居多。*

## 四、 底层执行顺序（必背）

为什么窗口函数**不能**直接写在 `WHERE` 后面？
因为 SQL 的执行顺序是这样的：

1.  `FROM` / `JOIN` （先拿表）
2.  `WHERE` （过滤原始数据）
3.  `GROUP BY`
4.  `HAVING`
5.  **`SELECT` （在这里执行 `OVER()` 窗口函数计算！）**
6.  `ORDER BY`
7.  `LIMIT`

**结论**：因为窗口函数在 `SELECT` 阶段才执行，而 `WHERE` 在它之前执行，所以 `WHERE` 里拿不到窗口函数的结果。**如果要对窗口函数的结果做过滤，必须套一层 `WITH` 或子查询，把结果变成新列后再在外层 `WHERE`。**

## 五、 三个极容易踩的坑

1.  **`LAST_VALUE` 的默认陷阱**：
    如果你直接写 `LAST_VALUE(字段) OVER (PARTITION BY x ORDER BY y)`，你会发现结果和当前行永远一样。
    **原因**：默认的窗口帧是 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`（第一行到当前行），当前行就是这一帧的最后一行。
    **解决**：必须手动加上 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`，让它看整个分区。
2.  **`ORDER BY` 的省略**：
    聚合类窗口函数如果不写 `ORDER BY`（如 `SUM(gdp) OVER (PARTITION BY continent)`），算的是整个分组的总和；一旦写了 `ORDER BY`，默认就变成了**累计求和**（从第一行累加到当前行）。
3.  **别名不能直接复用**：
    在 `SELECT` 中给窗口函数起了别名（如 `rank_col`），不能在同一个 `SELECT` 里用 `rank_col` 做运算，也不能在外层直接对同级别的列操作，必须套一层。

## 六、 万能代码模板（直接套用）

### 模板 1：求各类占比（Top-N + 占比）
```sql
WITH RankedData AS (
    SELECT 
        name, 
        category, 
        sales,
        SUM(sales) OVER (PARTITION BY category) AS category_total,  -- 分组总和
        ROW_NUMBER() OVER (PARTITION BY category ORDER BY sales DESC) AS rn  -- 组内排名
    FROM orders
)
SELECT 
    name, 
    category, 
    sales,
    sales * 100.0 / category_total AS pct_in_category -- 算占比
FROM RankedData
WHERE rn <= 3; -- 取每组前3名
```

### 模板 2：算累计/移动平均（时间序列）
```sql
SELECT 
    order_date, 
    daily_sales,
    -- 累计到当天的销售额
    SUM(daily_sales) OVER (ORDER BY order_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total,
    -- 近7天移动平均
    AVG(daily_sales) OVER (ORDER BY order_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS moving_avg_7d
FROM sales_table;
```

### 模板 3：算同比/环比
```sql
SELECT 
    month, 
    revenue,
    LAG(revenue, 1) OVER (ORDER BY month) AS last_month_revenue, -- 上个月的数据
    revenue - LAG(revenue, 1) OVER (ORDER BY month) AS mom_diff  -- 环比差值
FROM monthly_stats;
```
